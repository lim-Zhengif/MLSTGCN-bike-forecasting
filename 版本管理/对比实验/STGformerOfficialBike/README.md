# STGformer Official Core Bike B0

This directory is the auditable B0 adaptation of the official STGformer core
for the local Top-150 bike-flow contract:

```text
x [B, 168, 150, F] -> y_hat [B, 3, 150, 2]
```

The historical `版本管理/对比实验/STGformer` implementation is unchanged and
remains labelled as an STGformer-style baseline. The pinned upstream source and
license are recorded in `UPSTREAM.md` and `upstream/STGformer.py`.

The training entry point is self-contained inside this directory and does not
depend on the historical sibling `版本管理/对比实验/baseline_utils.py`.

B0 preserves the official learned adaptive graph. `dist.npy` is loaded only as
an external node-count/order audit. Multi-relation graph injection is deferred
to B1 so the official baseline and the innovation are not mixed.

Recommended environment:

```powershell
D:\Users\Administrator\miniconda3\envs\mlstgcn\python.exe `
  版本管理/对比实验/STGformerOfficialBike/train_stgformer_official_bike.py
```

Training and evaluation outputs are seed-aware. With no explicit
`--output_dir`, `--seed 1` writes to `b0_top150_hist168_pred3_seed1_bs16`
and `--seed 2` writes to the corresponding seed-2 directory. Evaluation also
checks that `--seed` matches the seed stored inside the checkpoint, so a
misnamed or overwritten checkpoint fails instead of being silently attributed
to the wrong run.

For checkpoints produced before this naming fix, pass the real file explicitly.
The output directory and file prefix will still be generated from the verified
seed:

```powershell
python 版本管理/对比实验/STGformerOfficialBike/evaluate_stgformer_official_bike.py `
  --device auto --seed 1 `
  --checkpoint "分析结果/对比实验/STGformerOfficialBike/b0_top150_hist168_pred3_seed0_bs16/best_stgformer_official_b0.pt"
```

When checkpoints already live in correctly named directories, the complete
oracle evaluations reduce to:

```powershell
python 版本管理/对比实验/STGformerOfficialBike/evaluate_stgformer_official_bike.py --device auto --seed 1
python 版本管理/对比实验/STGformerOfficialBike/evaluate_stgformer_official_bike.py --device auto --seed 2
```

No full training is started by repository setup. Run the tests first:

```powershell
D:\Users\Administrator\miniconda3\envs\mlstgcn\python.exe -m unittest discover `
  -s 版本管理/对比实验/STGformerOfficialBike/tests -p "test_*.py"
```

The evaluator labels its default same-day observed weather as
`oracle_observed_same_day`. Use `--future_weather_lag_days 1` for the
leakage-safe lagged-weather sensitivity run; the summary keeps the two regimes
separate.

The default holdout ends on 2026-06-30 and predicts `t+1..t+3`. Consequently,
the 21:00 anchor on that date needs trip counts through 2026-07-01 00:00. The
default `--trip_glob` therefore includes the July 2026 files. Copy those files
to the server before running the complete 976-anchor evaluation. If July data
is unavailable, `--end_date 2026-06-29 --trip_glob "20260[2-6]-citibike-tripdata*.csv"`
is a valid 968-anchor truncated run, but it is not the planned full-range
protocol.

The frozen B0 baseline uses seeds 0, 1, and 2 under the same model, data,
training, and oracle-weather evaluation contract. Its canonical manifest and
analysis are generated by:

```powershell
python 版本管理/对比实验/STGformerOfficialBike/freeze_b0_multiseed_baseline.py
```

Canonical outputs live in
`分析结果/对比实验/STGformerOfficialBike/b0_multiseed_baseline/`. B0 is immutable
after this freeze. Any sparse-demand gate or external-graph injection must use
a new experiment ID and retain B0 as the untouched control.

## G0 low-demand gate screen

G0 keeps the selected B0 checkpoint frozen and trains only a shared soft
suppression gate. Gate inputs are limited to B0 predictions, the previous 24
hours of observed directional demand, horizon, and target hour. The March-June
2026 holdout is not used for fitting or checkpoint selection.

```powershell
python 版本管理/对比实验/STGformerOfficialBike/train_b0_sparse_gate.py --device auto --seed 0
python 版本管理/对比实验/STGformerOfficialBike/evaluate_b0_sparse_gate.py --device auto --seed 0
python 版本管理/对比实验/STGformerOfficialBike/analyze_g0_sparse_gate.py
```

G0 is a seed-0 screening experiment. It advances only if external overall MAE
improves by at least 0.5%, zero-demand MAE improves by at least 15%, high-demand
MAE degrades by no more than 1%, and RMSE/net-flow MAE do not degrade together
by more than 1%. It is never merged into the frozen B0 artifacts.

The analyzer first requires exact prediction-key and truth equality with the
frozen B0 seed-0 holdout. It writes the machine-readable decision to
`分析结果/对比实验/STGformerOfficialBike/g0_screen_seed0/screen_summary.json`
and a concise Chinese report to the same directory. `ADVANCE_TO_B1` is emitted
only when every preregistered condition passes.
